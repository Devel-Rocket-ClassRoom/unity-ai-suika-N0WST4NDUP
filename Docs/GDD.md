# GDD — 수박 게임 (Suika Game Clone)

> 모든 이후 미션 구현 의뢰에서 본 문서를 컨텍스트로 함께 전달한다. 수치/명세가 충돌하면 본 문서가 우선이다.
> 코드 컨벤션·작업 흐름은 [../CLAUDE.md](../CLAUDE.md), 작업 분해는 [TASKS.md](TASKS.md) 참고.

---

## 1. 게임 개요

- **한 줄 요약**: 같은 과일을 합쳐 더 큰 과일을 만들고, 최종 수박에 도달하며 점수를 쌓는 물리 퍼즐 게임.
- **장르**: 캐주얼 / 물리 퍼즐 / 머지(Merge)
- **플레이 시간**: 한 판 2~5분 (게임오버 기준)
- **코어 루프**
  1. 상단 드로퍼에서 다음 과일을 X 위치에 정렬
  2. 드롭 → 물리로 자연스럽게 적층
  3. 같은 단계 과일이 만나면 한 단계 큰 과일로 머지 → 점수 가산
  4. 게임오버 라인 위에 과일이 일정 시간 머무르기 전까지 반복

---

## 2. 핵심 메커닉

### 2.1 떨어뜨리기 (Drop)

- 드로퍼는 보드 상단 고정 Y에서 X 축으로만 이동
- 입력: 마우스 X (1순위) / 좌·우 방향키 (보조)
- 드롭 트리거: 마우스 좌클릭 또는 Space
- 드롭 직후 **쿨다운 0.5초** 동안 입력 무시
- 드롭된 과일은 일반 Rigidbody2D 시뮬레이션 시작 (드로퍼 위에 있을 때는 Kinematic)

### 2.2 충돌·물리 (Collision)

- 2D 물리 사용 (URP 2D)
- 과일: `CircleCollider2D` + `Rigidbody2D (Dynamic)`
- 벽/바닥: `BoxCollider2D` + `Rigidbody2D (Static)` 또는 단순 콜라이더
- Physics Material: 약간의 반발(`bounciness ≈ 0.05`), 마찰(`friction ≈ 0.4`) — 데굴거리지만 튀지 않게
- 중력 스케일: 표준 (1.0)

### 2.3 머지 (Merge)

- 두 과일의 단계가 **동일**하고 충돌 발생 시 머지
- 머지 결과: 한 단계 큰 과일 1개를 두 과일의 **중점 위치**에 스폰
- 원본 두 과일은 즉시 비활성화 → 다음 프레임 Destroy
- **중복 머지 방지**: 머지 트리거된 과일은 즉시 `IsMerging` 플래그 set, 같은 프레임 내 추가 충돌 무시
- 최종 단계(11 / 수박)는 더 이상 머지되지 않음 (그대로 보드에 남음)
- 머지 시 점수 가산: 결과 단계의 `MergeScore` 값을 점수에 더함

### 2.4 게임오버 (Game Over)

- 보드 상단에 보이지 않는 **게임오버 라인** (드로퍼보다 약간 아래)
- 라인을 넘은 과일이 **연속 2.0초** 머무르면 게임오버
- 막 드롭된 과일은 **드롭 후 1.0초 동안** 게임오버 판정에서 제외 (안정화 유예)
- 게임오버 시: 입력 차단 → 결과 화면 모달 (점수 + 다시 시작)

## 3. 과일 단계

총 **11단계**. 스폰 가능한 과일은 단계 1~5만 (가중치 기반 랜덤). 단계 6 이상은 머지로만 등장.

| 단계 | 이름     | 직경(유닛) | 머지 점수 | 스폰 가능 | 가중치 |
| ---- | -------- | ---------- | --------- | --------- | ------ |
| 1    | 체리     | 0.50       | 1         | O         | 35     |
| 2    | 딸기     | 0.70       | 3         | O         | 25     |
| 3    | 포도     | 0.95       | 6         | O         | 20     |
| 4    | 데코폰   | 1.20       | 10        | O         | 12     |
| 5    | 감       | 1.50       | 15        | O         | 8      |
| 6    | 사과     | 1.85       | 21        | X         | -      |
| 7    | 배       | 2.25       | 28        | X         | -      |
| 8    | 복숭아   | 2.65       | 36        | X         | -      |
| 9    | 파인애플 | 3.05       | 45        | X         | -      |
| 10   | 멜론     | 3.45       | 55        | X         | -      |
| 11   | 수박     | 3.85       | 66        | X         | -      |

- **크기 규칙**: 단계 1~5는 약 1.4배 비율, 6~11은 약 1.18배로 완만 — 후반에 보드가 너무 빠르게 차지 않도록 조정
- **점수 규칙**: `MergeScore(n) = n * (n+1) / 2` (삼각수). 11단계 = 66점
- **머지 보너스**(자유 구현 후보): 첫 수박 등장 시 +500

스폰 가중치 합 = 100. 가중치는 향후 밸런스 표(자유 구현)로 외부화 후 튜닝.

---

## 4. 점수·승패 규칙

- **점수 가산 시점**: 머지가 발생한 순간, 결과 단계의 `MergeScore` 만큼 가산
- **명시적 승리 조건**: 없음 (캐주얼 무한 모드). 단, 수박(11단계) 생성 시 화면 연출 + 보너스 점수
- **패배 조건**: 게임오버 라인 위 과일 체류 2.0초
- **점수 표기**: 정수, 좌상단 HUD에 큰 폰트
- **최고 점수**(자유 구현 후보): `PlayerPrefs` 로 단순 저장

## 6. 톤 & 분위기

- **색감**: 따뜻한 파스텔. 배경은 옅은 크림/베이지, 과일은 채도 높지만 부드러운 톤
- **아트 방향**: 동글동글한 카툰. 외곽선은 약간 어두운 동일 계열 색으로 부드럽게
- **단계 구분**: 색상으로 한눈에 단계 식별 가능해야 함 (체리=짙은 빨강, 딸기=밝은 빨강, 포도=자주, ...)
- **BGM**: 잔잔하고 살짝 발랄한 캐주얼 톤 (자유 구현)
- **SFX**: 드롭(낮은 "통"), 머지(가벼운 "팝"), 게임오버(짧은 다운). 음정은 단계가 올라갈수록 살짝 높아지면 좋음

---

## 7. 빌드/플랫폼 가정

- **1차 타겟**: Windows Standalone (또는 에디터 플레이로 한 사이클 완주)
- **해상도**: 게임뷰 720 × 1280 (9:16 세로), 빌드 시 동일 비율 유지
- **렌더 파이프라인**: URP 2D
- **입력**: Unity Input System (`InputSystem_Actions.inputactions` 활용)
- **물리**: 2D (Physics2D 설정 Gravity = (0, -9.81))
- **에디터 버전**: Unity 6 LTS (또는 프로젝트 생성 시점 버전 그대로)

---

## 8. 디자인 결정 메모

- 단계 수 11은 오리지널 수박 게임 기준. 작업량/밸런스 모두 무리 없음
- 스폰 단계를 1~5로 제한해 머지 동기 부여를 확실히 함
- 드롭 쿨다운 0.5초 / 게임오버 체류 2초 / 안정화 유예 1초 — 모두 1차 추정값, 미션 1에서 플레이해보고 조정
- 점수 공식 삼각수는 단순·직관적. 자유 구현에서 콤보 보너스로 보강 가능
